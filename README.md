# Wikontic — выбор метода извлечения фактов

**Цель текущего этапа:** выбрать и зафиксировать один рабочий пайплайн
`заголовок + абзац → компактные факты (subject, relation, object, qualifiers)`.
Факты должны подтверждаться текстом, сохранять условия и не дублировать друг друга.
Число триплетов само по себе не является качеством или recall.

## Где мы сейчас

Реальные extraction-ответы нескольких промптов, повторные генерации и результаты
двух способов объединения уже сохранены. **Новые варианты пока не создаём —
сравниваем готовые в E08.** Лучший метод не установлен.

E08: 50 выбранных абзацев; merger завершён (47 структурных успехов / 3 ошибки);
основная автоматическая оценка 886 фактов и 200 пар подготовлена, labels пока нет.
Collection-1000 extraction и обучение компактной модели не выполняются на этом этапе.

## Следующий этап: E08

На одной фиксированной выборке сравниваются baseline_fixed, coverage, fewshot,
AutoOntik и четыре ensemble-варианта (heuristic/LLM × union/vote2).
Используются уже сохранённые predictions, без нового extraction или merger.
Оценка — один stateless LLM-judge проход по подготовленным фактам и парам;
рубрика, модель, выборка и политика повторов фиксируются до labels.

Итог — одна таблица judged precision, доступности, компактности, ошибок
эквивалентности и расхода ресурсов. Допустим неопределённый результат;
покрытие всех фактов текста и абсолютная точность судьи этим не устанавливаются.
Перед запуском требуется offline preflight и адаптация старого API-harness,
который пока ещё реализует неактуальные денежные ограничения.

## Зафиксированные решения

- Человеческой разметки на текущем этапе нет. LLM-оценки — exploratory silver,
  не независимый gold и не доказанная точность судьи.
- Денежного лимита экспериментов нет. Время/токены/стоимость сохраняются только
  для планирования трат; цена не является условием остановки или отбора методов.
- Число задач/вызовов, повторы и правила анализа фиксируются до результатов.
  Денежная свобода не означает бесконечные retries или необоснованные сетки.
- Существующие данные, ответы и locks не удаляем и не перезаписываем.
- Student training, downstream QA, дополнительные prompts/models
  и collection-1000 — отложенные направления, не очередь автоматических запусков.

## Структура и воспроизводимость

```text
src/ + scripts/ + tests/    реализация и проверки (наличие тестов ≠ качество фактов)
configs/methods/ + prompts/ сохранённые методы; исходники для сравнения не менять
schemas/                   контракт wikontic_facts_v1
data/                      входы, manifests, sampling, locks, calibration
runs/                      исходные ответы, ошибки и объединённые выдачи
reports/                   измерения, сравнения, литература и diff методов
external/                  публичные источники и source manifests
```

Данные: MuSiQue-Ans v1.0 train; tuning — 100 QA / 1863 уникальных абзаца,
collection — 1000 QA / 14281 подготовленный абзац. Extraction получает только
title+paragraph, не QA/decomposition. Exact overlap отсутствует по manifests;
near-duplicates/зависимость текстов отдельно полностью не проверены.

API-ключи — только во внешнем credentials-файле, окружении или игнорируемом local
config. Не коммитить секреты, `.venv`, IDE-кэш и сырой архив MuSiQue.
Локальные настройки инструментов, служебные планы и история взаимодействий
не входят в Git. README содержит краткое описание проекта без ссылок на них.
Они сохраняются на диске: существующие E08-locks ссылаются в том числе на
локальные protocol/TASK-файлы. Поэтому для полного воспроизведения E08 на другой
машине одного Git-checkout недостаточно — нужны все исходные файлы из locks,
включая исключённые документы. Locks не переписываются ради исключения из Git.
