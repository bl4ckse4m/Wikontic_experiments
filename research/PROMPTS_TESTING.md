# Сравнение промптов gpt-oss и модели B

Цель — выбрать промпт **отдельно для каждой модели**. Для оценки берём одни
и те же [50 абзацев](../runs/prompt_comparison/sample50.json) из MuSiQue-Ans v1.0
train (`tuning`, 100 вопросов и 1 863 уникальных абзаца). В запрос извлечения
идут системный промпт и заголовок с текстом одного абзаца, без вопроса MuSiQue,
ответа и соседних абзацев. Шаблон запроса — `render_messages()` из
[`extraction.py`](../src/wikontic_exp/extraction.py).

## Четыре промпта

| Метод | Файл |
|---|---|
| `baseline_fixed` | [`propmt_1_types_qualifiers_fixed.txt`](../prompts/baseline_fixed/propmt_1_types_qualifiers_fixed.txt) |
| `coverage` | [`coverage_v1.txt`](../prompts/candidates/coverage_v1.txt) |
| `fewshot` | [`fewshot_v1.txt`](../prompts/candidates/fewshot_v1.txt) |
| `autoontik` | [промпт AutoOntik](../prompts/autoontik/prompt_1_with_types_and_qualifiers.txt) |

## Как получены сохранённые ответы

| Выдачи | ID модели и маршрут | Настройки и объём |
|---|---|---|
| gpt-oss: `baseline_fixed`, `coverage`, `fewshot` | `Openai/Gpt-oss-120b`, основной endpoint института | `temperature=0.2`, `max_tokens=6000`, одна первичная генерация на абзац. 1 863 записи на промпт; в первичных выдачах обрезаны 2, 4 и 6 ответов соответственно. |
| gpt-oss: `autoontik` | `openai/gpt-oss-120b`, OpenRouter | `temperature=0.2`, `max_tokens=6000`, одна первичная генерация на абзац. 1 863 записи; один ответ обрезан. |
| gpt-oss: восстановление обрезанных выдач | Те же ID и маршруты, что для соответствующих промптов | `temperature=0.2`, `max_tokens=12000`. На институте приняли 12 ответов; для одного из них сохранились отдельно тайм-аут и успешный согласованный повтор. Для AutoOntik приняли одну отдельную выдачу OpenRouter. |
| Qwen: исторический пилот | `Qwen/Qwen3-235B-A22B-Instruct-2507`, основной endpoint института | `temperature=0.2`, `max_tokens=6000`; `baseline_fixed` на 11 текстах (5 абзацев MuSiQue, 6 синтетических), затем по одному повтору на каждом тексте. |

Точные конверты и параметры исторических вызовов сохранены в исходных
артефактах; `seed` в указанных запросах не задавали. Источники: [`data/answers/`](../data/answers/),
[`runs/prompt_recovery/`](../runs/prompt_recovery/) и
[`answers_complete.jsonl`](../runs/prompt_comparison/answers_complete.jsonl).
Последний файл содержит 7 452 готовых списка gpt-oss, включая все 200 списков
на выбранных 50 абзацах. Исторический AutoOntik отличается маршрутом API,
поэтому его результат нельзя приписать только тексту промпта. Дополнительный
режим [`qwen_missing`](../data/answers/qwen_missing.jsonl) получал на вход
готовый список фактов и не участвует в сравнении промптов. Сохранённые ответы
Qwen не пересекаются с выбранной выборкой.

## Настройки новых запусков

[`run_extraction.py`](../scripts/run_extraction.py) запускает модели
через endpoint института с `LLM_URL` / `LLM_KEY` из `~/.config/wikontic/creds`
(или `--creds-file`). Claude и OpenRouter скрипт не вызывает. Для
воспроизведения исторического AutoOntik через OpenRouter используйте
сохранённую выдачу: новый запуск `--model gpt-oss --prompt autoontik` идёт
через институт, то есть это другой маршрут.

| Настройка | gpt-oss | Модель B |
|---|---|---|
| Аргумент | `--model gpt-oss` | `--model-id ТОЧНЫЙ_ID` |
| ID в запросе | `Openai/Gpt-oss-120b` | Точный ID, выданный институтом |
| Температура (`--temperature`) | `0.2` | `0.2` |
| Первичный лимит (`--max-tokens`) | `6000` | `6000` |
| Лимит после обрезания (`--retry-max-tokens`) | `12000` | `12000` |
| Разбор и ожидание | `legacy`, чтение до `600` с, подключение до `20` с | Те же |

Для каждой пары «абзац × промпт» делается один запрос и **не больше одного
повтора**, только если сервер вернул нужный ID модели и `finish_reason=length`.
Меняется только `max_tokens`. Если снова `length`, результат остаётся
`truncated`, а не принимается как частичный список. Некорректный список при
`stop` получает `invalid_output`. Тайм-аут, HTTP-ошибка, несовпадение модели
или незавершённая запись о попытке блокируют продолжение без
автоматического повтора.

### Команды

Qwen3-235B сейчас недоступен. [`runs/qwen_tuning/`](../runs/qwen_tuning/)
содержит попытку с HTTP 404 и не содержит принятых выдач. Не использовать
эту папку для модели B. Алиас `--model qwen` по-прежнему относится только
к историческому ID, а не к будущей замене.

Из корня проекта, без `--execute` — план на 50 абзацев без ключа и сети.
Замените `Institute/EXAMPLE` на реальный ID, когда он станет известен:

```bash
.venv/bin/python scripts/run_extraction.py --model-id Institute/EXAMPLE \
  --sample runs/prompt_comparison/sample50.json \
  --out-dir runs/model_b_sample50
```

Добавьте `--execute --limit 8` для технической проверки первых двух абзацев
с четырьмя промптами. `--limit` считает пары, а не HTTP-запросы: повтор после
`length` — дополнительный запрос. Та же команда с `--execute` без `--limit`
возобновит запуск и закончит эту выборку. Полный `tuning` при необходимости
запускается отдельно: `--all`, опционально `--sample-first`, другая папка
запуска. Можно ограничить промпты повторяемым `--prompt`.

В папке запуска `config.json` фиксирует ID примеров, тексты и хеши промптов,
параметры, хеш endpoint, версии и хеши кода. В `jobs/` сохраняются запросы,
необработанные тела ответов, токены и стоимость, если их вернул API, а также
статусы и разобранные триплеты. `answers.jsonl` — сводка завершённых пар со
ссылками на исходные попытки. Ключи не записываются. Для изменения настроек или
маршрута нужна новая папка запуска.

## Как сравниваем

Claude проверяет **один полный список на запрос**, не видя модель извлечения,
название промпта и другие списки. На тех же 50 абзацах считаем Precision и
размер выдачи, отдельно для каждого промпта внутри каждой модели. Для двух
моделей и четырёх непустых выдач на каждый абзац это до 400 запросов Claude,
а не разметка всех 1 863 абзацев. Размер выдачи на всём `tuning` — справочный
показатель, не recall.

### Разметка подтверждённости и таблица

Для сохранённых выдач gpt-oss следующий вызов покажет план на 200 списков:

```bash
.venv/bin/python scripts/run_judging.py \
  --sample runs/prompt_comparison/sample50.json \
  --answers runs/prompt_comparison/answers_complete.jsonl \
  --out runs/prompt_comparison/gptoss_sample50_grounding.jsonl
```

Без `--execute` API не используется. `--execute --limit 4` выполнит только
первые четыре задания. Для последующего продолжения используйте тот же
`--out` с теми же настройками. Для модели B подставьте её `answers.jsonl`
и новый `--out`. Судья по умолчанию — `anthropic/claude-sonnet-5.5` через
OpenRouter; ключ `openrouter_key` берётся из локального файла. Промпт
подтверждённости не изменён. Принимается JSON без обёртки или в одном
Markdown-блоке, с ровно одной меткой `0/1` на каждый ID.

Соседняя папка `<out>.jobs/` сохраняет манифест, запросы, сырые ответы с
`usage`/`cost`, если API их вернул, и результаты. `--out` — сводка. При
возобновлении принятые задания не отправляются, а тайм-аут и незавершённая
попытка не повторяются. Записи из старого `judgments_full.jsonl` не
переносятся в новую выборку.

```bash
.venv/bin/python scripts/score_judgments.py \
  --sample runs/prompt_comparison/sample50.json \
  --answers runs/prompt_comparison/answers_complete.jsonl \
  --judgments runs/prompt_comparison/gptoss_sample50_grounding.jsonl \
  --out runs/prompt_comparison/gptoss_sample50_scores.json
```

Precision — число меток `1` / число триплетов на общих оценённых абзацах.
Рядом выводится размер выдачи на тех же абзацах. При неполной разметке
таблица помечается как неполная: отдельно считаются отсутствующие и пустые
выдачи, ошибки и ещё не отправленные оценки. Описательный парный bootstrap
для разниц с `baseline_fixed` ресэмплирует абзацы, не триплеты. Он не
валидирует судью и не объявляет победителя автоматически.

### Объединение выдач

[`run_dedup.py`](../scripts/run_dedup.py) принимает два JSONL (`--left`,
`--right`) с выбранными промптами (`--left-method`, `--right-method`) и
общую выборку (`--sample`). Для двух вариантов используйте те же входы в том
же порядке, но разные `--model-id`, `--method` и `--out`. ID дедупликатора
должен принадлежать одной из этих двух моделей института. Он получает
объединённый список с ID от нуля и общий [промпт](../prompts/merger/partition.txt).
Ответ — `groups`, в каждой группе `members` и `representative`. Кандидат
обязан входить ровно в одну группу, а представитель — быть её участником.
В итоговый список идут исходные триплеты-представители без переписывания.
Ошибочный ответ сохраняется как `invalid_output`, без попытки восстановить
пропущенные ID. Запуск по умолчанию показывает план; реальные вызовы только
с `--execute`.
Для оценки двух одиночных и двух объединённых выдач вместе
`run_judging.py` и `score_judgments.py` принимают четыре аргумента
`--entry ИМЯ МЕТОД ФАЙЛ` вместо одного `--answers`.

**Отдельной проверки дублей Claude нет.** Судья проверяет только
подтверждённость по тексту. В таблице показываем размер выдачи, число
подтверждённых триплетов и Precision. Полное разбиение по ID не доказывает
смысловую уникальность, поэтому таблица не оценивает её или полноту.

**Статус:** инфраструктура проверена с подставными ответами, без новых
запросов к моделям. Схема эксперимента — [EXPERIMENT_FLOW.md](EXPERIMENT_FLOW.md).
